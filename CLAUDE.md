# SohoArchTimes — постоянные правила проекта

Этот репозиторий — сайт-слайдшоу SohoArchTimes (GitHub Pages) и вся операционка канала.
Telegram-канал: @SohoArchTimes · публичная лента: https://t.me/s/SohoArchTimes · бот: @ArchTimesBot · chat id: -1003823260493.
Полная спецификация — HANDOFF.md. Пошаговый процесс публикации — ops/runbook.md.

## Железные правила
- Никакой автоматики: никаких scheduled tasks, routines, auto-fix и фоновых запусков. Публикация в канал и обновление сайта — только по прямой команде пользователя в текущей сессии.
- Токен бота существует только в env-переменной TELEGRAM_BOT_TOKEN (настройки cloud environment). Репозиторий публичный: токен никогда не писать в файлы, коммиты, логи и вывод. Если токен обнаружен в файле или диффе — остановиться и сообщить пользователю.
- Ключи и доступы (Yandex Cloud, SSH к VM, Hoster, GitHub-токен и пр.) НЕ хранить в репозитории. Их резервная копия — в приватной папке Google Drive «SohoArchTimes-Secrets»; карта и процедура восстановления — ops/SECRETS.md. В сессии ключи держать в .secrets/ (под .gitignore).
- Публикация только через ops/publish_album.py (Bot API sendMediaGroup). Telegram-коннекторы не использовать.
- Реестр публикаций ops/published_objects.json — единственная защита от дублей. Публикация не завершена, пока обновлённый реестр не попал в main: если работа идёт в ветке — открыть PR, самостоятельно смержить его (инструменты GitHub MCP) и проверить, что изменения реально в origin/main.
- PR-ы, мерджи и прочие операции GitHub Claude выполняет сам; пользователя к кнопкам GitHub не привлекать (его прямое указание, 2026-08-24). К пользователю идти только если не хватает доступа.
- ops/archive/ — история старой среды, только для справки: не редактировать, не удалять, в скриптах не использовать.

## Отбор объектов
- Только built / completed projects, площадь ≥ 1000 м². Если порог не подтверждается надёжно по разрешённому источнику — объект пропускать.
- Источники только ArchDaily и Parametric Architecture. Любые другие источники для подбора объектов запрещены.
- Тематика: parametric architecture, computational design, digital/robotic fabrication, advanced material systems, responsive facades, computational envelopes, data-driven structures. Если связь с парадигмой слабая или натянутая — пропуск.
- Не ограничиваться павильонами: активно брать headquarters, музеи, культурные здания, кампусы, research centers, transport hubs, towers, high-rise/mid-rise, крупные общественные и mixed-use объекты.
- Ровно 5 надёжно скачиваемых качественных изображений, иначе пропуск. ArchDaily → прямые images.adsttc.com …/large_jpg/…; Parametric Architecture → прямые …/wp-content/uploads/….
- В альбом — только фотографии готовой архитектуры разрешением не ниже 1280 px по длинной и 700 px по короткой стороне; при этом предпочитать кадры, у которых у источника есть original с короткой стороной ≥ 1800 px — на сайт-витрину проходят только такие. Чертежи, схемы, референс-пейзажи «источников вдохновения», фото стройки и кадры, где здание не читается, в альбом не брать.
- Интерьеры — только с явной параметрической архитектурой (криволинейные оболочки, ветвящиеся опоры, параметрические решётки/потолки, цифровая фабрикация). Ортогональные лобби, офисы, торговые залы и прочие интерьеры, которые могли быть спроектированы и построены и 30 лет назад до ЧПУ, не брать.
- Дубли запрещены абсолютно: проверять source_url, canonical_source_url, title и очевидные варианты названия, включая кросс-источниковые, по ops/published_objects.json.

## Подпись
- Только русский. Без ссылки на источник и без упоминания источника.
- Формат: название; локация; архитектор; год реализации (если известен); материалы (если известны); краткое описание.
- Материалы — конкретно и содержательно; «стекло, бетон, сталь, дерево» как единственное описание запрещены; названия продуктов, поставщиков и брендов не переводить; если конкретики нет — строку «Материалы» опустить.
- Качество текста — уровень хорошего поста V on Shenton. Перед публикацией проверять логическую консистентность, фактическую корректность и корректность описания конструкций. Сомнение в факте — факт не писать. Никаких выдумок и слабых формулировок.

## Что считается успешной публикацией
- После отправки проверить публичную видимость: https://t.me/s/SohoArchTimes и прямой URL поста. Успех — только если пост реально виден публично как альбом ровно из 5 изображений; иначе публикация неуспешна, брать следующего кандидата.
- Если задача — публикация одного объекта, продолжать, пока не подтверждён ровно 1 новый публично видимый пост.

## Сайт
- Источник истины — публичная видимость в Telegram. Пост младше 12 часов на сайт не попадает. Удалённый из канала пост убирается с сайта. Если у публичного поста стало меньше изображений — сайт это повторяет. Картинок, которых нет в Telegram, на сайте быть не должно.
- Правило качества витрины (указание владельца 2026-08-25, сознательное исключение из «сайт повторяет телеграм» — в сторону строгости): никаких картинок меньше 1800 px по маленькой (короткой) стороне — в slides.json попадают только кадры с короткой стороной ≥ 1800 px; лучше убрать кадр с витрины, чем показывать мыло. Если основной URL мельче, сборщик подставляет тот же кадр в полном разрешении (adsttc: размерный сегмент → /original/; файл тот же); не дотянул и оригинал — кадр с витрины снимается. В url_fallback каждого кадра сборщик ставит копию из нашего архива (см. ниже), при её отсутствии — прежний URL. Превью t.me/s (≤ 800 px) не проходят никогда. Размеры сборщик берёт из кэша ops/site_data/image_dimensions.json (ведёт сам, руками не править), новые URL измеряет по сети. Кадры без архитектуры (референс-пейзажи, чертежи, фото стройки) и интерьеры без явной параметрической архитектуры (указание владельца 2026-08-25: ортогональные лобби/офисы/торговые залы, которые могли быть построены и 30 лет назад до ЧПУ, на витрине не нужны) снимаются с витрины вручную через ops/site_data/slide_blocklist.json (mid + idx + причина). Полные каталоги ops/site_data/* фильтр не трогает — он действует только на slides.json.
- Масштаб на экране (решение владельца 2026-08-25): кадр рисуется в натуральном размере 1:1 (clampToNatural в app.js), крупные кадры заполняют экран с обрезкой краёв. Вариант «вписывать целиком с уменьшением» был опробован и ОТМЕНЁН владельцем («верни как было») — не возвращать без его прямого указания.
- Пересборка: `python ops/build_sohoarchtimes_catalog.py` — пишет ops/site_data/* и slides.json в корне репо. Формат slides.json: id, mid, idx, title, arch, year, loc, url, post, src; сортировка newest first по message_id, внутри поста — по порядку изображений; записи с src="proven_high_res" не понижать до превью.
- Кнопка ⟳ на сайте запускает .github/workflows/rebuild.yml (workflow_dispatch, GitHub-токен пользователя хранится только в его браузере): Action пересобирает slides.json по текущему публичному Telegram и коммитит в main только при изменениях. Это ручной запуск по нажатию — расписаний не добавлять.
- Архив кадров витрины (страховка от смерти первоисточников, по решению владельца 2026-08-25): каждый кадр slides.json зеркалируется в бакет soho-archtimes-site под img/ (имя файла = sha256 содержимого, перезапись невозможна; манифест — ops/site_data/image_archive.json в репо и копия img/manifest.json в бакете). Зеркалирование — вручную по команде: `python ops/mirror_showcase_images.py` (ключи S3 из env/.secrets, в репо им нельзя); прогонять после каждой публикации, когда новый пост дошёл до витрины. Сборщик ставит архивную копию в url_fallback — если ArchDaily/PA удалят файл или закроют хотлинк, сайт сам переключится на архив без потери качества. Манифест руками не править.
- ops/publisher_proof.json — точное соответствие «пост → исходные image_urls»: пополняется ops/publish_album.py при каждой успешной публикации, читается сборщиком (единственное основание тира proven_high_res). Вручную не редактировать и не удалять.
- Превью t.me/s (cdn*.telesco.pe) протухают за 1–2 недели — если на сайте массово битые картинки, первым делом пересборка и деплой slides.json.
- Не полагаться на кэш как на источник истины. Задача обновления завершена, только когда живой сайт https://sl-himmelreich.github.io/sohoarchtimes-slideshow-site/ и публичный slides.json реально отдают свежие данные; при задержке GitHub Pages — подождать и перепроверить.
- Сайт живёт на ДВУХ площадках, правки всегда деплоить на обе: (1) GitHub Pages (этот репозиторий, main) и (2) клон https://archtimes.sohoai.ru — Yandex Object Storage, бакет soho-archtimes-site (folder b1gb3dbv6atsou7hqe62), раздаётся через Yandex CDN (ресурс bc8qd5…/bc8ru4nyb63phwwwkcbx, сертификат в Certificate Manager). Заливать index.html, app.js, styles.css, slides.json в бакет по S3 API (ключи — у владельца/в env, в репо им нельзя). Кастомный домен на GitHub Pages НЕ настраивать никогда (файл CNAME ломает github.io редиректом).

## Календарный ассистент (ops/tg_gcal/)
- Личная система владельца «Telegram → Google Календарь»; к каналу, публикациям и сайту отношения не имеет. Детали: ops/tg_gcal/README.md; правила разбора: ops/tg_gcal/PARSING_RULES.md (не менять без прямого указания владельца).
- Постоянная система (по прямому указанию владельца 24.08.2026 «процесс должен идти без Claude») существует в двух вариантах, Claude-сессий не запускает и правилу «никакой автоматики» не противоречит: (А) Google Apps Script ops/tg_gcal/apps_script/Code.gs в аккаунте владельца, ежедневно ~21:00 МСК, метка событий «[планировщик GAS]»; (Б) GitHub Actions `.github/workflows/calendar-assistant.yml` (21:00 МСК; секреты — только в Actions secrets). Их расписания не трогать; других расписаний это не разрешает. Включение — ops/tg_gcal/SETUP.md.
- Пока ни один вариант не включён, действует временный мост — Routine «SOHO Calendar Assistant — мост 21:10 МСК» в постоянной операционной сессии; это единственное разрешённое исключение из правила «никакой автоматики». Каждый запуск моста выполняет только ops/tg_gcal/ROUTINE.md (включая шаг 0 — самоудаление, когда любой постоянный вариант заработал); публиковать в канал и менять сайт ему запрещено.
- Механика: getUpdates без offset, подтверждение offset строго в конце безошибочного запуска; обрабатывается только личный чат владельца (1294602429). Токен — тот же TELEGRAM_BOT_TOKEN.
