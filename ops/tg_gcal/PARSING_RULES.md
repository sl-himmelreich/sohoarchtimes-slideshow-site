# SOHO Calendar Assistant — правила разбора сообщений в события

Перенос правил работавшей системы (142 запуска, 194 события).
НЕ МЕНЯТЬ без прямого указания владельца.

## Константы
- Обрабатывается ТОЛЬКО чат `1294602429` (личный чат владельца с @ArchTimesBot).
  Игнорировать: channel_post (включая каналы), команды на «/», нетекстовое,
  любые другие чаты — это фильтрует `tg_pipeline.py fetch`.
- Календарь: primary подключённого Google-аккаунта (Google Calendar MCP).
- TZ Europe/Moscow (+03:00). Длительность по умолчанию 60 мин; дата без
  времени → 09:00.
- База ВСЕХ относительных дат — message.date сообщения в МСК (поле `date_msk`
  из fetch), НЕ момент запуска.

## Даты
- «N месяца» / «N.MM» / «DD.MM.YYYY» — как написано; без года — ближайшая будущая.
- «N числа» — ближайшее N-е (прошло — следующий месяц).
- «сегодня / завтра / послезавтра / через N дней» — от message.date.
- День недели («в среду») — ближайший будущий; если сегодня этот день и время
  впереди — сегодня.
- «следующий вторник» / «во вторник на следующей неделе» — день следующей
  календарной недели (недели с понедельника).

## Время
- Форматы: HH:MM / HH-MM / HH.MM / «HH часов MM минут».
- «HH утра» (06–11), «HH дня» (12–17), «HH вечера» (HH+12), «HH ночи» (00–05).
- Числительные словами из диктовки («двадцать один тридцать» → 21:30).
- «утром» → 09:00, «днём» → 13:00, «вечером» → 19:00, «ночью» → 22:00.
- Времени нет → 09:00, в description добавить «Время не указано — утренний блок.»

## Длительность
- «N мин / N часов»; «полчаса» = 30; «час» = 60; «полтора часа» = 90.
- Диапазон «с 14 до 16» / «14:00–16:00» → start/end по диапазону.
- Не указана → 60 мин.

## Повторы
- «ежедневно» → RRULE:FREQ=DAILY.
- «каждый понедельник» / «по понедельникам» → RRULE:FREQ=WEEKLY;BYDAY=MO
  (аналогично остальным дням недели).
- «по будням» → RRULE:FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR.
- «N числа каждого месяца» → RRULE:FREQ=MONTHLY;BYMONTHDAY=N, первое
  срабатывание — ближайшее будущее N-е.
- Ограничение периода («в августе по понедельникам») → добавить UNTIL (в UTC).

## Структура
- Несколько дел в одном сообщении → отдельные события.
- «14:00 отъезд, 20:00 приезд» → одно событие 14:00–20:00.
- Сообщение-уточнение без даты в пределах ~30 мин после предыдущего —
  трактовать в контексте предыдущего.
- Лишняя оговорка («завтра» при явном дне недели) — дата из дня недели,
  оговорку в description: «Контекст: «…»».

## Название и description
- Название — суть после даты/времени; убрать стартовые «внеси / запиши /
  поставь / добавь / создай» (и искажения диктовки вроде «неси в календарь»);
  первая буква заглавная.
- description всегда начинается с «Из Telegram».

## Не событие
- Приветствие, вопрос, обсуждение прошедшего без «внеси/запиши» → ответ ⚠️
  (формат ниже), событие не создавать.
- Если дата есть, а неоднозначно только время — событие создать с 09:00, без ⚠️.

## Дубли
- Перед созданием КАЖДОГО события — проверка: в календаре на ту же дату уже
  есть событие с тем же/почти тем же названием → пропустить, отметить в логе
  запуска (в Telegram об этом не сообщать).

## Подтверждения владельцу (sendMessage в 1294602429, всё по-русски, эмодзи только ✅ и ⚠️)
- Одно событие: `✅ Добавлено: [название], [ДД.ММ], [ЧЧ:ММ]`
- Несколько: `✅ Добавлено N событий:` и далее строки
  `• ДД.ММ (Дд) ЧЧ:ММ — Название`
- На каждое нераспознанное: `⚠️ Не удалось распознать событие. Пример формата: «3 апреля 14:00 30 мин встреча с Петровым»`
- Пустой запуск — полная тишина, никаких уведомлений.
